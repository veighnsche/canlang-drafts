# CanRent browser acceptance

[Source](../CanRent.can) and [requirements](../CanRent.md) own this app's behavior. The local entry uses the shared suite to derive current selection, routes and inline examples; it starts the real dev preview and refuses unsupported runtime coverage. No parallel app manifest is authoritative.

```sh
bun run test:draft -- CanRent/playwright/app.spec.ts
bun run test:draft:coverage -- CanRent
```

Selected-app compilation must establish which routes belong to each declared composition.

Browser setup requires verified team identities with `billing` grants. The default Ava/Ben preview memberships have no custom role grants; team ownership is insufficient. Provision owning records and declared file/provider resources under their actual authority before populated journeys; record an unavailable binding with its owner and release condition.

Required app journeys:

- Two customers request the last pooled seat: one succeeds, the other receives current availability without duplicate capacity/allowance consumption. Failed counterpart holds release once; money overage remains visible until fulfilled.
- Reception sees an overdue occupied room despite its planned end; explicit checkout clears occupancy. A failed reschedule preserves the original booking, and late payment without capacity enters refund/alternative review rather than admission.

Required browser states include the permitted empty and populated route, in-flight canonical submission, validation error with corrected retry, failure with retained input, denied route/control/direct request, and reload of committed data. Exercise only states meaningful for the declared operation; provider uncertainty must retain its app-defined state rather than becoming success. Check desktop and narrow-screen navigation, focus, labels, dialogs/drawers, filtering/paging and personal settings where authored.

Exact authored empty captions: “No locations yet”; “No weekly hours yet”; “No closed dates yet”; “No date hours yet”; “No matching retained bookings”; “No retained bookings”; “No finance exceptions”; “No confirmed bookings”; “No movement credits”; “No movement credit refunds”; “No adjustments”; “No resources match these filters”; “No day calendars yet”; “No availability windows”; “No bookings yet”; “No capacity revisions yet”; “No desks yet”; “No venue reservations”; “No quote holds”; “No unresolved conflicts”; “No repair blocks”; “No workspace moves”; “No correspondence yet”; “No bookings to handle”; “No bookings in this view”; “No measures in this window”.

Semantic browser journey bodies for the workflows above remain unimplemented until the real role/data/resource setup is available. Passing source examples and route checks do not establish all functionality or every UI state. Coverage must keep this gap visible and must not convert it into skipped, placeholder or passing semantic tests.

`references/` holds design concepts; these are not screenshots of a running app. Actual captures and comparison results belong in results, and accepted runtime baselines remain separate. Tolerant visual checks should compare composition, spacing, readability and responsive structure while allowing small rendering/font differences; reference similarity alone cannot establish functional correctness. Missing references, baselines, captures or semantic states remain explicit coverage gaps.
